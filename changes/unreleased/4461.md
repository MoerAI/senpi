## 2026-10-27 - Sign-in runs claude auth login, then a connection test (senpi#4436, S5)

### What changed

- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/oauth-login.ts`: `createOAuthConfig().login` no longer runs the senpi-owned PKCE flow (`loadAnthropicOAuth` is gone from the login path; the `loginFlow` dep is removed). It asks for the account name first (same `Name for this account (...)` prompt), then relays the method select `Select Anthropic login method:` / `Browser login (default)` / `Copy code login (headless)` through `onSelect` (a host with no select callback gets the browser login), refuses an already-aborted login before anything is spawned, ensures the account dir (a new random `dirId`, or the slot's own for a Reconnect), and runs `startClaudeCliLogin` (`claude auth login --claudeai`). `auth_url` carries the captured browser URL, or the manual URL in copy-code mode; the paste prompt is titled `Paste the code Anthropic shows after you sign in:` with the manual URL as its placeholder, and a blank answer pastes nothing. On exit 0 `claude auth status` must report a first-party claude.ai login; its email, organization and plan become the slot `profile`, with `signedInAt`. A Reconnect keeps the name, display name, model blocks, pin and order and clears `signInRequired` and the block fields. One cleanup scope covers everything after the account dir exists (sign-in, `auth status`, the first store write, the connection test). Any throw or cancel puts the slot back as it was (no slot for a new account), signs out a CLI login this attempt made (`claude auth logout`), and removes a new account's dir. A connection test cut short by a cancel is a cancelled login, not a kept account.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-connection-test.ts` (new): `connectionTestModel` (the default model when the default provider is `anthropic-subscription`, else `defaultModelPerProvider["anthropic-subscription"]`) and `runClaudeCliConnectionTest`: one "Reply with OK" turn through `queryWithAuthLane`, pinned to the new account with `accountFallback: false`, no tools, `settingSources: []`, `persistSession: false`, `maxTurns: 1`, 60 s budget. The outcome is stored as the slot's `check` (`classifySdkError` kind as `reason`, never error text); a failed test keeps the account. Progress lines report the test and its result.
- The new slot is written to the store only for the test and taken back afterwards, so the login commit (`Models.login` / `AuthStorage.set`, which merge under the credential lock) still adds it and names it in the account receipt; a Reconnect keeps its in-place write, which is what the commit merge sees.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/claude-cli-login-outcome.ts` (new): the account and check of the sign-in that ran under a login's signal, taken once by the RPC handler.
- `packages/coding-agent/src/core/extensions/builtin/anthropic-subscription/index.ts`: wires the default model (settings `defaultProvider`/`defaultModel`), the provider settings and the cwd into the sign-in.

### Why

- senpi#4436: Claude subscription sign-in moves to the bundled Claude Code CLI's own login, so senpi never holds or refreshes Claude tokens for these accounts, and each new account is tested right after sign-in on the model the user's turns will use.

### Why an extension could not handle it

- The login, account slots and turn lane are this builtin provider's own OAuth config and account machinery.

### Expected merge conflict zones

- HIGH: `login` in `oauth-login.ts` (rewritten) and its deps type.
- LOW: the `createOAuthConfig` deps literal in `index.ts`.

## 2026-10-27 - auth_login_end names the Claude account and its connection test (senpi#4436, S5)

### What changed

- `packages/coding-agent/src/modes/rpc/connection-handler.ts`: a successful `auth_login_end` for a Claude CLI sign-in also carries `account` `{name}` and `check` `{model, outcome, reason?, at}`, taken once by the login's own signal. `docs/rpc.md` documents both.

### Why

- senpi#4436: a client shows which account was signed in and whether its connection test passed, without re-reading the account list.

### Why an extension could not handle it

- `auth_login_end` is emitted by the RPC login handler itself.

### Expected merge conflict zones

- LOW: the success branch of `startLogin` in `connection-handler.ts`.
