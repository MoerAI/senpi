## 2026-11-14 - A run language wrapped in quote or whitespace junk is recovered (senpi#6618)

### What changed

- `src/tool/eval-argument-validator.ts`: before the missing-field check, `recoverRunLanguage` strips quote and whitespace junk from a run call's string `language` that is not already a language. An enabled language left after stripping (`js"` becomes `js`) is used; anything else counts as omitted, so the existing inference (senpi#5154) or the missing-language teaching error applies. An exact language, enabled or not, and a non-string value still go to the schema. When the call then fails generic validation for another reason, the error reports the caller's own arguments, as it already did for an inferred language.

### Why

- A quoting slip such as `"language": "js\""` failed with the generic anyOf dump (`language: must be equal to constant; ...`), which a model cannot act on, because only an omitted language reached inference (senpi#6618).

### Why an extension could not handle it

- The eval argument validator is the codemode package's own registered validator for its schema.

### Expected merge conflict zones

- LOW: the top of `validate` in `registerEvalArgumentValidator`, and the helpers above `fillInferredLanguage`.

### Fixed

- `eval` recovers a run language wrapped in quote or whitespace junk (for example `js"`), and treats any other non-language value like an omitted language, so inference or the missing-language error applies instead of the generic schema error ([#6618](https://github.com/code-yeongyu/senpi/issues/6618)).
