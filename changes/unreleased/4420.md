## 2026-10-27 - Publish agent_settled before its extension handlers (senpi#4420, oh-my-openagent#11419)

### What changed

- `packages/coding-agent/src/core/agent-session.ts`: `_emitAgentSettled` publishes `agent_settled` to session subscribers before it awaits the extension `agent_settled` handlers; the handlers still run inside the deferral window, so turns they request start after every settled handler finishes. `prompt()` releases still-held settled handler waits (the existing `releaseHeldHandlers` path) when a person's input arrives while that window is open; the handler keeps running and is logged as `extension_handler_stalled` with `stage: "released"`.

### Why

- One slow or hung `agent_settled` handler held every client's settle edge (desktop "Starting session...", TUI "Working") for up to the 20 min host cap, and held the person's next prompt behind it. `agent_settled` is notification-only.

### Why an extension could not handle it

- The order of the session's own event publication and its prompt admission are owned by `AgentSession`; an extension cannot publish the settle earlier or release another extension's held wait.

### Expected merge conflict zones

- LOW: `_emitAgentSettled` in `agent-session.ts` (two adjacent lines swapped plus a comment).
- LOW: the person-input branch at the top of `prompt()` in `agent-session.ts` (one added guard line).
